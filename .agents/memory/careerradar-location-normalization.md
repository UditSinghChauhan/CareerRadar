# Location normalisation (Phase 2.0)

- `jobs.country` is unreliable and is read NOWHERE. The schema default writes 'India' for every row whose provider omitted it (all 554 RemoteOK rows), and SmartRecruiters writes lowercase ISO-2. It stays in place (additive-only) but every filter uses the six derived columns: `location_city/_region/_country/_metro`, `is_india`, `is_remote`.
- `normalizeLocation(raw, providerCountry)` in `artifacts/api-server/src/relevance/location.ts`. The `providerCountry` hint is ONLY ever the value a provider emitted for this job in this run (`ProviderJob.country`) or a country in a POST/PUT body. The backfill passes nothing, and `jobsService.update` must not fall back to the stored column — it did once, and the schema default turned 'Posts, ' into an India row.
- Rule 6 is the one that matters: unmatched → `is_india = NULL`, never false. `false` is only for strings that name somewhere else. The Jobs page's `unknown` bucket is `is_india IS NULL`.
- Adzuna (largest source, /jobs/in/ endpoint, sampled 2026-09-14): 31% of results are bare 'India'; the second token is often a DISTRICT, not a state — 'Noida, Ghaziabad', 'Palwal, Faridabad', 'Kochi, Ernakulam', 'Devanahalli, Bangalore Rural'. `IN_DISTRICTS` exists for this.
- Two-letter codes are resolved in a second pass with country context: 'TN' is Tamil Nadu unless the string is already US, 'IN' is India unless US (Indiana). Multi-country lists ('LATAM, Europe, USA') record no single country; a scope that includes APAC/Asia is not "scoped away from India".
- Location filtering is SERVER-SIDE (`?locations=`, `?isIndia=`, `?isRemote=`). The page fetches 200 rows of 2,850+; a browser-side pass would silently miss matches. Buckets OR together; the `remote` bucket is `is_remote AND is_india IS NOT false` so 'Remote - US' stays out of the default feed.
- Backfill is recompute-all (deterministic → idempotent, no skip-if-set flag), keyset-paginated by id in 500s, writes only the six columns and never `updated_at`. Production runs it via `POST /api/admin/backfill-location` (no shell on Render); the response carries the full bucket distribution and `unknownActivePercent` — the target is under 10%.
- Buckets (2026-09-15): `india_unspecified` = `is_india AND location_metro IS NULL` (bare 'India' — 31% of Adzuna) is separate from `other_india` (a named non-hub city) and IS in the defaults. Measured before the split: 950 whole-word internship-titled active rows, only 331 in the default feed, 267 of the missing ones were bare-India. "Didn't say where" ≠ "said somewhere else".
- `is_remote` also comes from the provider's `workMode === "remote"` (RemoteOK/Jobicy are remote-only boards; their `location` is the poster's town). Without that signal 378 RemoteOK rows sat in `unknown` (12.4%); with it plus the district/suffix/foreign-town pass, unknown is 0%.
- For Phase 2.1: `job_type = 'internship'` covers 856 active rows vs 950 by whole-word title match (`\m(interns?|internships?|fresher|fresh graduate|graduates?|trainees?)\M`). The provider-supplied jobType is a strong signal in its own right; do not derive everything from the title. The crude `intern|fresher|graduate|trainee` regex over-matches ("internal", "international") — 1,052.
